Коротко: щоб почати ранжуватися російською, потрібно не лише “теги”, а локалізовані сторінки/метадані (title/description/OG/Schema) і коректні hreflang. У твоєму Angular-проєкті це робиться доволі просто й поступово—від “мінімальних правок” до повної двомовності.

Варіанти інтеграції

1. Мінімальний (швидкий старт, без зміни роутингу)
   • Додай hreflang для російської у index.html:

<link rel="alternate" hreflang="ru-UA" href="https://www.advocate-pensia.com.ua/"/>
<meta property="og:locale:alternate" content="ru_UA"/>

(У тебе вже є uk/uk-UA/x-default—просто додаємо ru-UA.)

    •	Розшир оголошення OG/Twitter: залиш og:locale = uk_UA, але додай og:locale:alternate як вище.
    •	JSON-LD: у поточному блоку можна додати "inLanguage": ["uk-UA", "ru-UA"].
    •	Мікрододавки російських ключів – meta keywords історично майже не впливають, але не зашкодить додати вкручено російські синоніми на самих сторінках (h1/h2/текст). Найкраще — короткий російський абзац у ключових місцях (герой/FAQ).

✅ Це майже без коду, але ефект обмежений, бо немає окремих RU-URL.

2. Правильно з точки зору SEO (окремі RU-URL)

Стандарт: сторінки українською та російською з дзеркальними URL і hreflang-зв’язками.

Що зробити в Angular: 1. Додати префікс мови в роутинг (наприклад, / для укр і /ru для рос):
• Створити два набори маршрутів або один з параметром :lang(uk|ru) і редірект з головного домену на uk.
• Додати перемикач мови в UI. 2. Зробити локалізовані SEO-дані. У тебе є централізований SEO-конфіг (GLOBAL_SEO_CONFIG). Додай мовні варіанти:

// PageSEO як є, додамо обгортку
export type LocalizedSEO = { uk: PageSEO; ru: PageSEO };

export const SEO_DATA_LOCALIZED: { [key: string]: LocalizedSEO } = {
main: {
uk: {
title: 'Поддяча Юлія Юріївна | Адвокат по пенсіях в Україні',
description: 'Професійні адвокатські послуги…',
keywords: 'адвокат по пенсії, пенсійний адвокат, …',
canonical: '/',
},
ru: {
title: 'Поддячая Юлия Юрьевна | Адвокат по пенсиям в Украине',
description:
'Профессиональная юридическая помощь по пенсионным вопросам. Оформление пенсии без вашего присутствия в ПФУ. Опыт 10+ лет.',
keywords:
'адвокат по пенсиям, пенсионный адвокат, юрист по пенсии, Поддячая Юлия Юрьевна, перерасчёт пенсии, оформление пенсии, помощь пенсионерам, судебная защита',
canonical: '/ru',
},
},
// ...about-me / services / contacts / blog аналогічно
};

І змінити сервіс SEO так, щоб він:
• читав поточну мову з маршруту,
• брав відповідний uk/ru блок,
• виставляв <link rel="canonical"> на свою мову,
• додавав альтернативи hreflang парою:
• для uk-сторінки: hreflang="uk-UA", alternate → ru-URL, і x-default на головну;
• для ru-сторінки: навпаки.

    3.	OG/Twitter/JSON-LD – мовні варіанти:
    •	На uk-сторінках: og:locale = uk_UA, og:locale:alternate = ru_UA;
    •	На ru-сторінках: навпаки (ru_UA як основний).
    •	JSON-LD дублюй з локалізованими полями (name, description, inLanguage = ru-UA на RU-версії).
    4.	Блог: у твоєму BLOG_SEO_DATA додай для кожного поста ru-метадані. Опційно — російські версії контенту під blog/:slug ↔ blog/ru/:slug, із двостороннім hreflang.
    5.	Sitemap: генеруй дві локалізовані версії кожної URL з <xhtml:link rel="alternate" hreflang="...">. Це сильно підсилює правильну індексацію.
    6.	SSR (Angular Universal) — якщо ще не увімкнено, рекомендується для кращого краулінгу та швидшого TTFB для ботів.

3. Проміжний варіант (без повного перекладу контенту)
   • Залишаєш uk-контент, але створюєш російські лендінги для ключових запитів (головна, послуги, контакти, 1-2 топові статті).
   • Налаштовуєш hreflang-зв’язки тільки для тих сторінок, які справді маєш у двох мовах.
   • Поступово додаєш RU-версії інших сторінок.

Що важливо знати
• Meta keywords ≠ ранжування. Працює реальний контент, заголовки, внутрішні посилання, hreflang, швидкість, E-E-A-T.
• Якість перекладу. Автопереклад без редагування може знизити конверсію. Краще вичитати й адаптувати терміни (“перерахунок пенсії” → “перерасчёт пенсии” тощо).
• Гео-мітки. Для російської краще ставити hreflang="ru-UA", бо ціль — російськомовні користувачі в Україні.
• Дублі. Кожна мовна сторінка має власний canonical і взаємні alternate. Не міксуй дві мови на одній URL.

Конкретні кроки для тебе (практично) 1. index.html (мінімально додай):

<link rel="alternate" hreflang="ru-UA" href="https://www.advocate-pensia.com.ua/"/>
<meta property="og:locale:alternate" content="ru_UA"/>

І в JSON-LD додай "inLanguage": ["uk-UA","ru-UA"]. 2. Розширити SEO-сервіс/конфіги:

    •	Додай LocalizedSEO (приклад вище).
    •	У GLOBAL_SEO_CONFIG/BLOG_SEO_DATA для ключових сторінок пропиши RU-title/description.
    •	У сервісі, що ставить метатеги, визначай мову з URL (/ru/...) і підставляй відповідний блок + став og:locale, canonical, alternate.

    3.	Роутинг /:lang (коли будеш готовий):

    •	Додай префікс /ru і дублікати сторінок.
    •	Зроби перемикач мови.

    4.	Sitemap:

    •	Згенеруй для кожної сторінки пару URL (uk/ru) з <xhtml:link> для hreflang.

Хочеш — можу одразу підготувати патчі для:
• index.html (hreflang/OG/JSON-LD),
• нового seo.config з RU-полями для main/services/contacts/blog,
• приклад змін у SEO-сервісі (визначення мови й виставлення метаданих).
